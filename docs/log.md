* **Decision (deviations from the 2026-10-03 plan)**: (1) the option marker is a *learned vector* substituted at placeholder positions, not a new `<|opt|>` vocabulary token, so no embedding resize and the 262k embedding matrix can stay frozen; (2) no per-kind bias, only a per-kind scale, because a bias is invisible to a softmax; (3) `L_bp_cycles` keeps the checkpoint's `[3,3]` by default instead of `[0,3]`; (4) fp32 master weights with bf16 autocast; (5) bekko test rows are hashed for the leakage guard but never written out.
* **Create**: Code for conversion, mixture building, overlap audit, training, calibration and evaluation, with 53 tests; how to run it: [training-setup](/design/training-setup.md).
* **Finding**: Source schemas differed from what the dataset cards suggested. tasksource noul rows have empty `options` and one target value (P(true)); its validation split's `split` column says `dev`; LocalLLaMA's real columns are JSON strings (`state`, `questions`, `gold`); MASSIVE is a loading script, so its source archive is read directly; HelpSteer2 has no test split (its validation becomes our test); bekko licences live per upstream dataset in `sources.json` with review statuses, and most subsets are "qualified" (excluded by default).
* **Fix** (each found by running something, not by reading): HelpSteer2 ids collided across upstream splits (caught by the builder's final id check); the LocalLLaMA converter silently produced nothing until checked against real rows; the `dev` split alias made the first builds drop all 15,000 tasksource validation rows; a batch in which every decision was too long crashed collation; the letter-baseline prompt tokenized `\n\n` as two tokens unlike the real tokenizer (caught by the network test against `apply_chat_template`); a concurrent-download race on the MASSIVE archive.
* **Finding**: Exact-hash leakage checks are not enough. The same example reaches us via different collections with different renderings. A word 12-gram fingerprint guard, compared against other sources' eval rows only, caught real cases: bekko vs tasksource twins (cladder, corr2cause), `bekko/aqua_rat` vs `tasksource/math_qa`, and 5 of 1,038 HelpSteer2 validation responses that also occur in HelpSteer2 train. The first version compared within a source too and wrongly dropped 1,345 LocalLLaMA decisions (templated data); fixed and covered by a test.
* **Finding**: Mimir v1.5 trained on `tasksource__`, `flan__`, `posttrain_natural_instructions__` and similar. A name-level audit flags nearly everything we can use (316/316 tasksource, 7/7 bekko, 5/5 HelpSteer2, 2/2 MASSIVE); only LocalLLaMA (4 sources) is unflagged. My earlier suggestion that `massive/nb-NO` is clean held-out evidence was wrong and is corrected in [dataset-selection](/design/dataset-selection.md).
* **Finding**: In a toy synthetic task the slot model learned shuffled-option decisions quickly while the letter baseline needed a fixed option order. This checks the mechanism only; it is not evidence about the real model.
* **Verification**: 50 offline tests plus 3 network tests pass (the network ones check the prompt against the real tokenizer and that saved checkpoints reload to the same logits). Each of the three leakage guards (state hash, group id, n-gram) was disabled in turn and the suite failed every time. A smoke run of build, train, calibrate and evaluate worked end to end for both models on a tiny random HRM with the real tokenizer (CPU). A trial build (4,000 rows per source and split) ran in about 70 s and passed all assertions. **Not done**: the full build, any run of the real 1.8B model, GPU memory measurement, row-level overlap with Mimir's data. No result about decision quality exists yet.
* **Note**: Two tooling slips cost time without affecting results: an interactive `cp` prompt hung a mutation test (the mutated file was restored and verified identical), and a duplicate background build raced on a shared cache.
